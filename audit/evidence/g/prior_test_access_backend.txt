## d4_eval.py docstring
"""D4: the locked test set through the deployed pipeline, once per model, scored by viet-ocr-eval.

    mkdir -p reports/eval/d4
    setsid nohup uv run python tools/d4_eval.py >> reports/eval/d4/run.log 2>&1 < /dev/null &
    uv run python tools/d4_eval.py --status          # progress, from anywhere

For each model (base, then adapted; one model served at a time, decision D4):
1. Stop every inference server, start the layout server and N recognition servers for this model,
   recreate the worker against them, and register or confirm the model version.
2. Upload the 3,978 locked test pages through the API: one document per book, in chunks of at most
   100 pages. VieBookRead page and book ids are attached, and D2 means each model gets its own upload.
3. Submit one job per document with text_policy page-v1 (decision D5), wait, and resubmit failed
   jobs (at most twice; pages already done are skipped).
4. Export the machine manifest, join the locked references by page_id (tools/join_reference.py),
   and score it with `viet-ocr-eval score`.
Then `viet-ocr-eval compare base adapted` gives the paired result.

Resumable: every upload, job and finished stage is recorded in <out>/state.json as it happens, so
running the script again after a crash or reboot continues where it stopped: no upload twice, and
the same idempotency keys. Everything goes under reports/eval/d4/ (not in git: it holds book text).
The locked tables in training/finals/ are never touched.

These numbers measure the whole deployed system: PP-DocLayoutV3 regions instead of ground-truth
polygons. They are an additional result next to the locked tables, not a replacement (D4).
"""
